# MyCut 0.9.1 — зоны кнопок: скорость, близость, инерция

Обновление **0.9.2 Unified zones**: основной запуск теперь ведёт в `out/MyCut-unified`. Тот же закон и настройки применяются к кнопкам/полям, объектам сцены, углам/рёбрам масштаба, обоим способам поворота, портам и телам нод, ручкам и телам клипов. Общий базовый радиус — **Base zone radius / DIP**. Native bridge получает те же speed coefficient / influence / shrink / threshold / cap, что и WPF. Debug кольца масштаба/поворота используют те же сохранённые радиусы. Старые ControlMargin/ObjectMargin сохранены в JSON только для совместимости, отдельными радиусами в текущем интерфейсе не управляют. Ниже — описание предыдущего среза 0.9.1.

Запуск: `Start-MyCut.cmd` → `out/MyCut-zones/MyCut.exe`. Старая 0.9 сохранена в `out/MyCut-sketch`.

## Новый закон

Для WPF-кнопок, полей, списков, checkbox/combobox:

```text
d = расстояние от мыши до ближайшего края элемента, DIP
близость = max(0, 1 − d / расстояние_влияния)²
добавочный_радиус = min(лимит, max(0, скорость − порог) × коэффициент_скорости × близость)
зона = обычный margin + сохранённый добавочный радиус
```

Внутри элемента d = 0. Направление движения больше не отсекает зоны кнопок: главное — скорость и близость. Направленный прогноз остаётся у gizmo/native controls и в prediction debug. Порог можно установить в 0, тогда используется скорость без вычитания порога.

Каждый элемент хранит собственный радиус. Увеличение происходит сразу. Уменьшение ограничено величиной `скорость_сжатия × прошедшее_время`; повторные mouse events не перезапускают таймер уменьшения. После ~60 ms без новых перемещений текущая скорость для кнопок считается нулевой, а расширенную область удерживает именно память элемента, не старый прогноз движения. Скрытый элемент при повторном появлении учитывает всё прошедшее время. Память слабая: удалённые UI controls не остаются удержанными ею.

При пересечении зон выбирается ближайшая доступная поверхность элемента; центр разрешает равное расстояние. Старое большое поле не должно перехватывать клик у более близкой доступной кнопки. Hover, click и debug используют один радиус и одно правило.

## Настройки

MyCut → Interface settings / Debug → Interaction zones:

| Поле | По умолчанию | Значение |
|---|---|---|
| Mouse speed coefficient | 0.04 | усиление скорости |
| Distance influence / DIP | 160 | дальность влияния близости |
| Zone shrink / DIP/s | 88 | скорость уменьшения: меньше = дольше сохраняется зона |
| Fast-motion expansion | 44 | лимит добавочного радиуса |
| Speed threshold / DIP/s | 260 | игнорировать медленную точную работу; 0 отключает порог |

Пример: полный добавочный радиус 44 DIP при сжатии 88 DIP/s возвращается к обычному margin за 0.5 s после начала уменьшения. При 44 DIP/s — за 1 s. Это скорость, не фиксированный таймер: меньшая зона возвращается быстрее. Сила косметических анимаций задаётся отдельно и не отключает input inertia.

Новые параметры входят в JSON preset и сохраняются; старые presets версии 1 получают значения по умолчанию для отсутствующих полей. Native canvas handles и NodeCanvas ports пока используют прежний направленный закон и полусекундный release; новый закон в этом срезе относится к обычным UI controls.

## Проверки

- Console interface suite: влияние скорости/расстояния/коэффициента, cap/threshold, независимые зоны, постоянная скорость уменьшения при частых retargets, изменение скорости сжатия и моментальное повторное расширение.
- Windowless model suite: ближайший допустимый элемент, отсутствие зависимости кнопок от направления, отделение текущей скорости от forecast.
- GUI smoke: actual bound commands / proximity clicks, новые settings fields и roundtrip presets, settings clip-boundary regression.

Это уточнение input engine, не новая анимация визуального размера кнопок. Elastic reflow остаётся отдельным механизмом.
