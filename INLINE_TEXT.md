# Редактирование текста на канвасе

Текущая сборка: `out/MyCut-inline-text`, запуск через `Start-MyCut.cmd`.

## Управление

- Выбрать инструмент T и нажать на существующий текст; щелчок по пустому канвасу создаёт новый текстовый слой и открывает его для ввода.
- Двойной щелчок по тексту инструментом перемещения также включает текстовый режим.
- Перетаскивание мышью выделяет фрагмент текста. Доступны ввод кириллицы, несколько строк, Delete/Backspace, Ctrl+A/C/X/V, Shift+стрелки и обычная навигация курсора.
- Enter добавляет строку. Ctrl+Enter или щелчок вне редактора применяет изменения. Esc отменяет сеанс.
- Пока ввод активен, Ctrl+Z/Y отменяет/возвращает текстовые правки. После применения один Undo документа откатывает весь сеанс, включая изменения размеров области и позиции.
- Параметры шрифта остаются в верхней панели; щелчок вне ввода сначала применяет текущий сеанс. Заблокированный текст недоступен для ввода.

## Устройство

`InlineTextEditor` размещает настоящий WPF TextBox поверх GPU-канваса, с матрицей положения, масштаба по двум осям и вращения экземпляра. Он принадлежит той же живой 3D-поверхности интерфейса: курсор и выделение участвуют в её перспективной проекции. Текст остаётся обычным редактируемым содержимым существующего слоя, без изменения MYCUT 6.

Изменения идут через существующую модель и общий native gesture. Auto-fit измеряет текст прежним DirectWrite-путём; при росте области положение экземпляра корректируется так, чтобы левый верхний угол не смещался. Видимые связанные экземпляры получают изменения общего определения как раньше.

`mc_editing_text` — временное состояние предпросмотра, отдельно от pointer style и документа. Только активный экземпляр пропускается при отрисовке native preview, чтобы не рисовать буквы дважды. Экспорт и сохранение продолжают использовать полное содержимое слоя; временное скрытие в них не записывается.

## Исправление ошибки Visual

Всплывающий WPF Popup может логически наследовать `SpatialWorkspace.Owner`, но находится в отдельном визуальном дереве. Раньше это приводило к `TransformToAncestor` для чужой ветки. `SpatialCoordinates.SurfaceFor` теперь проверяет реальное визуальное родство; popup использует свои экранные координаты, а преобразование основной поверхности выполняется только для её настоящих потомков. Это исправление причины, а не перехват/подавление исключения.

## Границы реализации

Это plain-text редактирование с общим оформлением слоя, не rich-text с разными шрифтами отдельных слов. Во время ввода используется WPF-представление текста; итоговое сглаживание, метрики, подчёркивание, Tint/Grade и node-эффекты определяются native renderer после применения. Очень длинный текст за границами композиции обрезается границами канваса, а не областью слоя. Физическая работа IME, системного буфера обмена и mixed-DPI на нескольких мониторах требует ручной проверки.
