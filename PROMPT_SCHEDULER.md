# Python: промпт в сохранённую сессию по времени

Откройте `Prompt-scheduler.cmd`. Вставьте текст или загрузите UTF-8 `.txt/.md`, оставьте дату пустой и время `01:40`, нажмите «Назначить отправку» и подтвердите. Если 01:40 уже прошло, выбирается следующий день. Точное время можно задать датой `YYYY-MM-DD`. Программа ждёт один раз и запускает официальный `codex exec resume` с конкретным UUID этого чата: `01a13594-289a-77e2-9d27-583903848d4a`.

Командная строка:

```powershell
python scripts/prompt_scheduler.py --at 01:40 --prompt-file "мой-промпт.txt"
python scripts/prompt_scheduler.py --at 2026-10-15T01:40 --prompt-file "мой-промпт.txt" --dry-run
```

Это **не** имитация клавиатуры/кнопки Send и не отдельный новый чат: CLI получает точный ID сохранённой сессии. Официальные источники: [non-interactive resume](https://learn.chatgpt.com/docs/non-interactive-mode), [scheduled tasks in a chat](https://learn.chatgpt.com/docs/automations). Для гарантированного запуска непосредственно через интерфейс приложения альтернативой являются встроенные scheduled tasks в текущем чате; они здесь не создавались, так как пользователь ещё не дал текст ночного задания.

Ограничения:

- Проверены таймер, UUID, UTF-8 stdin, dry-run и отказ при слишком позднем пробуждении. **Реальная отправка и немедленное отображение CLI-сообщения в окне Codex не проверялись**, чтобы не запускать новый ход в занятой сессии. Обновление может потребовать переоткрытия чата. Первый короткий тест лучше выполнить вручную, когда чат свободен.
- Не запускайте это параллельно с активной работой в том же чате. Скрипт не может надёжно проверить активность desktop-сервера.
- ПК не должен спать, сеть и процесс Python должны оставаться работающими. Используется местное время Windows; на этой машине проверена зона FLE Standard Time (Киев). После опоздания более 3 минут отправка отменяется, а не происходит неожиданно после пробуждения.
- Codex должен быть авторизован. Скрипт не читает токены, не меняет sandbox/approval/model, не применяет bypass-флаги и не обходит лимиты. CLI использует свои действующие настройки/сохранённую сессию; доступ к изменениям проекта может зависеть от них.
- Для каждого задания допускается одна попытка. При ошибке, нехватке лимита или неоднозначном результате автоматических повторов нет: они могли бы дублировать уже принятый промпт. Файлы задания и журнала находятся локально в `out/prompt-scheduler`; они могут содержать личный текст, не публикуйте их.
- Закрытие окна отменяет ожидание, но не отзывает уже начавшуюся CLI-отправку. Сохранённые задания не запускаются автоматически при следующем открытии окна. Их можно запустить явно через `--job путь.job.json`.

Python 3.12 и Codex CLI найдены на этой машине. Пакеты/API key не требуются. Тесты: `python tests/test_prompt_scheduler.py` — 6 passed, реальный Codex не запускается.
