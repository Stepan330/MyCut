# MyCut UI Core и docking

Новая стартовая сцена для проверки этих компонентов: [UI Lab](UI_LAB.md). Числа тестов ниже относятся к этапу внедрения docking; текущий workspace после добавления Lab и fixed HorizontalBox — 84 passed.

Реализовано в Rust-версии. Старый C++/WPF интерфейс не переписывался. Общие компоненты используют готовые egui widgets, а не собственную реализацию текстового ввода и раскладки.

## Где менять базовые элементы

### Единый Outliner

`app/src/ui_core/outliner.rs` — единственная реализация строк, колонок, поиска, сортировки, раскрытия и видимости для **всех Outliner текущей Rust-программы**: Photo Editor (Local/Global, docked/перемещённый), UE Study, Concept и Components. Нельзя создавать отдельный renderer строк для новой панели: передавайте `OutlinerRow` и обрабатывайте `Action`.

`OutlinerRow` содержит стабильный `u64` ID модели, подпись, тип, иконку и видимость. Выбранный ID — `Option<u64>`, включая пустой документ. `OutlinerOptions` задаёт путь корней, высоту и название счётчика; `Outliner` хранит только состояние представления. Оформление применяется локально, не меняя остальные панели. У каждой панели свой экземпляр состояния, но общий код. Демонстрационные сцены используют собственные данные, не фото-документ.

Photo Editor использует `in_scene_order()`: верхний слой сверху, без алфавитной пересортировки. Клик по заголовку меняет только порядок отображения. Выбор связан с Details/Canvas, видимость проходит через существующую команду и Undo/preview. Добавление, дублирование, удаление и перестановка слоёв сохранены в адаптере приложения. Формат проектов и legacy C++/WPF не менялись. Корни Global можно сворачивать независимо; поиск временно раскрывает их, Local не зависит от свёрнутого Global. Полноценное дерево Prefab/reparent и multiselect пока не добавлены.

`app/src/ui_core.rs`:

| Компонент | Назначение |
|---|---|
| TextBlock | Обычные, маленькие, выделенные и цветные подписи через UiComponents. |
| InputField | Текстовый ввод; egui сохраняет каретку, выделение, clipboard и текст внутри рамки. |
| NumberField, ParameterSlider | Числовой ввод/drag и slider; ограничения задаёт вызывающий код. |
| Button | Общая кнопка, selected, min size, локальная политика анимации. |
| HorizontalBox | Фиксированный контейнер: симметричное перераспределение вокруг растущего ребёнка, минимальные размеры и clipping. |
| FlowBox, Spacer | Обычные intrinsic/wrapped строки и интервалы на основе egui. UiComponents.hbox/flow_box — совместимые helpers этих обычных строк. |
| Window | Общие диалоги: movable, resizable, collapsible, размер, open state. |
| IconButton (`icons.rs`) | Иконки поверх Button, общий renderer и анимация размеров/подсветки. |

Основные панели, параметры, поиск, ввод текста на канвасе, тулбары и диалоги переведены на эти компоненты. Специализированные ComboBox, деревья, color picker и docking chrome остаются готовыми контролами egui/Craft UI с общей темой; не создавалась копия их механизмов. Палитра и метрики — `theme.rs`.

```rust
use crate::{icons::{Icon, IconButton}, ui_core::{Button, Feature}};
ui.add(Button::new("Apply").animation(Feature::Off));
IconButton::new(Icon::Save, "Save project")
    .animation(Feature::Off)
    .show(ui);
```

Feature = Inherit / On / Off. Иерархия: глобальное значение → политика панели → настройка отдельного компонента. Глобальная сила 0 отключает движение полностью. При Off собственный аниматор кнопки не вычисляется и не запрашивает кадры анимации. ComponentPolicy.adaptive_input управляет дополнительным радиусом обычных widgets; настройки манипулятора остаются в Interaction.

## Панели

### Поверхности концепта

`app/src/ui_core/surface.rs`: переиспользуемые `SurfaceStyle`, `Panel`, `PanelHeader`, `Toolbar`, `Toggle`. Стиль задаёт фон, заливку, обводку, текст, акцент, цвет переключателя, радиус и толщину линии. Панели получают стабильный ID и прямоугольник от владельца раскладки, обрезают содержимое по внутренним границам и не владеют данными документа. Toggle поддерживает enabled/changed, widget metadata и общую политику анимации. Иконки Pointer/Cube — кодовая геометрия.

`app/src/ui_lab/concept.rs` повторяет эскиз этими компонентами с сохранением пропорций. Это демонстрация UI, не подмена рабочего Canvas/Outliner. Движок, docking и форматы проектов не менялись. В обычном запуске UI Lab открывает Concept; Components возвращает галерею. Настройки Concept локальны для сессии, пока без сериализации.

### Расчёт HorizontalBox

Реализация: `app/src/ui_core/horizontal_box.rs`. `HorizontalBox::new([width,height]).gap(gap).show(ui,items,focus,body)` принимает BoxItem с neutral basis, minimum и desired. При изменении desired сохраняется центр активного ребёнка. Левая и правая стороны уступают по половине прироста: сначала перемещаются в свободное место, затем сжимаются до minimum. Дальнейший рост ограничивается; контейнер не растёт и не переносит детей на другую строку. На краях рост также ограничен границами контейнера. Если физически не помещаются даже minima, они пропорционально ослабляются, а содержимое обрезается по слотам.

Родитель не измеряет детей повторной отрисовкой: геометрия рассчитывается из descriptors за O(n), body вызывается один раз на ребёнка, ID привязан к индексу слота. При одном изменённом ребёнке focus можно не задавать; при нескольких одновременно приложение явно задаёт активный индекс (иначе выбирается наибольшее отклонение от basis). Ребёнок должен учитывать полученный available_size; длинный текст штатных кнопок обрезается, не расширяя слот.

В UI Lab оба ряда кнопок («02» и «02b») используют fixed HorizontalBox. Пять кнопок «02b» стартуют одинаковыми, без выбранного Center; ручной desired применяется только при включённом Manual resize (opt-in), в том числе для старых пресетов. При размере 600, preferred gap 8 и minimum gap 4 ручной центральный desired 280 даёт ширины 76/76/280/76/76. Старые строки тулбаров относятся к FlowBox.

Между каждой парой детей и по краям создаётся эластичный спейсер. `.gap(preferred)` задаёт предпочтительный внутренний зазор, `.minimum_gap(minimum)` — нижнюю границу (по умолчанию 4 DIP, не больше preferred). Свободное место делится между всеми n+1 спейсерами. При нехватке места сначала сжимаются спейсеры, затем дети. Для невозможных minima в слишком узком родителе сохраняется безопасное пропорциональное уменьшение. Внутренние спейсеры не создают widgets и не меняют ID детей; их ширины сглаживаются вместе со всей раскладкой через `.duration(seconds)`.

Контейнер сглаживает всю геометрию слотов, а не только ширины: смена hover-anchor не вызывает мгновенной перестановки соседей. Общая интерполяция сохраняет порядок и границы. `.duration(seconds)` задаёт плавность; общая animation off отключает её. Изменение размера родителя применяется сразу, чтобы не рисовать детей за новыми границами.

`app/src/workspace.rs`: PanelId (стабильный ID), PanelDefinition (название, минимум размера, возможности), PanelSettings (блокировка и ComponentPolicy), Workspace (раскладка и сохранение), Content (адаптер содержимого). Реестр: Canvas, Tools, Details, Outliner, Content Browser. Документ и выделение не принадлежат окнам.

### Управление

1. Потянуть заголовок-вкладку панели.
2. Навести на край другой области: подсветка показывает будущее закрепление. Центр совместимой панели объединяет вкладки.
3. Отпустить мышь. Escape, потеря фокуса или отпускание вне допустимой области отменяют перенос.
4. Разделители меняют размеры панелей.
5. Правый клик по вкладке: блокировка позиции, анимации, перемещение в группу, закрытие.
6. Settings → Panels: восстановление скрытых панелей, блокировка, анимации, Reset workspace layout.

Canvas защищён от закрытия и перемещения, не принимает вкладки поверх себя; закреплять панели по краям можно. Floating запрещён и renderer permissions, и обработчиком команд. Неверная операция атомарна и не теряет панель.

Автосохранение раскладки после жеста: `%LOCALAPPDATA%/MyCutNext/workspace.json`. Формат проекта не менялся. Ограничение 64 KiB, проверка версии/дерева/уникальности, атомарная запись через tempfile. Повреждённый файл даёт сообщение и стандартную раскладку. Headless tests и capture-режим не пишут пользовательские настройки.

## Готовая библиотека

Craft UI, категория A, commit `8f5a2831614e632f91ad367f7af2a6e5b61b9529`, `crates/ui`, MIT option. В `vendor/craft-ui` включена библиотека, не редакторы и не branded assets. Все 20 исходных файлов совпадают по SHA256 с исследованным checkout. Cargo.toml адаптирует workspace metadata и фиксирует egui 0.36.2. Лицензии, NOTICE и UPSTREAM.md сохранены; зависимости — уже используемые egui/serde.

Форматирование: `cargo fmt -p mycut-next -p mycut-photo-core`. Не использовать `cargo fmt --all` для vendor: он форматирует также path dependencies.

## Проверка

49 тестов: 29 app + 20 core. Новые: наследование/override политик, запрет Float/закрытия Canvas/перемещения locked панели, атомарность неудачного переноса, hide/restore с сохранением позиции и политик, повторная запись workspace, повреждённый JSON, pointer drag к краю и в центр, Escape/focus loss/invalid drop, сохранение состояния документа и Undo, Fit по размеру панели. Clippy `-D warnings`, сборка и форматирование собственных пакетов успешны.

Настоящее GPU-окно: RTX 5060 Ti/Vulkan. Снимки: docking-check.png, docked-left-check.png, panel-settings-check.png. Полный upstream suite заново не запускался: проверены интеграционные сценарии MyCut и ранее component gate.

Ограничения: один viewport, без native cross-window/multi-monitor docking, auto-hide и произвольных перекрывающихся абсолютных позиций. Верхняя командная и контекстная строки — оболочка, не dock-панели. OS-level физический ввод/IME не проверены. Settings и подтверждения остаются диалогами через общий Window. Это не рефакторинг Data/Prefab/рендерера.
